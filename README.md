# astrbot_plugin_arknights_recruit

《明日方舟》公开招募词条计算插件。发送一组公招词条，算出**每个词条组合能招到哪些干员**。

## 指令

```
/公招 <词条> [词条 ...]
```

词条之间用空格分隔，最多 5 个（与游戏内一致，超出直接报错）。不带词条时会收到一句抱怨。

## 计算依据

插件的结论完全来自游戏机制，不是拍脑袋的经验表：

1. **词条是"与"关系。** 招募结果必须同时满足所选的全部词条；若某个组合下没有任何干员，游戏会随机丢弃部分词条再抽。因此插件枚举所选词条的**所有非空子集**，对每个子集求干员交集——和 PRTS 的计算器算法一致。所以输入 `支援 输出 近战位` 会同时给出 `支援`、`支援+输出`、`支援+近战位` 等 7 个组合的结果。

2. **默认展示所有时长下的可能结果。** 招募时长会决定能出的星级区间，官方 `gacha_table.recruitRarityTable` 规定：

   | 时长 | 可出现星级 |
   | --- | --- |
   | 0:10 ~ 3:50 | 1★ ~ 4★ |
   | 4:00 ~ 7:30 | 2★ ~ 5★ |
   | 7:40 ~ 9:00 | 3★ ~ 5★ |

   默认（`recruit_time = all`）不按时长裁剪，把该组合在**任意时长下**可能出现的干员全部列出，所以 1★ 机械、2★ 新手这类只在短时长出现的干员不会被藏起来。每个组合标题右侧的徽章标出该池子的星级区间（如 `1★~5★`）。

   如果把 `recruit_time` 设成具体时间，就会按上表裁剪到该时长能出的星级。例如 `支援` 在 9:00 下只剩 `4★~5★` 的 8 名干员（1★ 的 Castle-3 不在池内），而在不限时长下是 `1★~5★` 的 10 名。另外 `高级资深干员` 可突破上限直接出 6★，`资深干员` 可出 5★（`specialTagRarityTable`）。

3. **干员池与词条来自游戏数据。** 打包的数据集源自 [MaaAssistantArknights](https://github.com/MaaAssistantArknights/MaaAssistantArknights) 的 `resource/recruitment.json`（160 名公招干员），并与游戏内 `gacha_table.recruitDetail` 列出的官方池、以及 PRTS 的公招数据逐条比对过。限定干员（年、W、迷迭香等）不在池内。

## 词条输入

29 个正式词条：

```
先锋干员 近卫干员 狙击干员 重装干员 医疗干员 辅助干员 术师干员 特种干员
近战位 远程位 高级资深干员 资深干员 新手
费用回复 输出 防护 生存 群攻 减速 治疗 支援 削弱 位移 召唤 快速复活 爆发 控场 支援机械 元素
```

支持简写与常见错写：

| 输入 | 解析为 |
| --- | --- |
| 高姿 / 高资 | 高级资深干员 |
| 资深 | 资深干员 |
| 回费 / 费回 | 费用回复 |
| 防御 | 防护 |
| 支援器械 / 器械 | 支援机械 |
| 近战 / 远程 | 近战位 / 远程位 |
| 近卫 / 狙击 / 重装 / 医疗 / 辅助 / 术师 / 特种 / 先锋 | 对应的"XX干员" |
| 快速 | 快速复活（唯一前缀匹配） |
| 复活 / 快活 | 快速复活 |

匹配顺序为 **正式词条全等 → 别名表 → 唯一前缀**。任何一步无法唯一确定都不猜：认不出的词条会被列出来报错，有歧义的会给出候选。

### 怎么改别名表

别名表就在 [core/tags.py](core/tags.py) 顶部的 `ALIASES` 字典里，键是**规范化后**的输入（去掉空白、全角转半角），值是正式词条名：

```python
ALIASES: dict[str, str] = {
    "高姿": "高级资深干员",
    "高资": "高级资深干员",
    "回费": "费用回复",
    # 加一行就生效，重启插件即可
    "招唤": "召唤",
    "群伤": "群攻",
}
```

几点注意：

- **值必须是 `TAGS` 里的 29 个正式词条之一**，写错的话这个词条永远匹配不上。改完可以直接跑 `python tests/selftest.py` 验证。
- **全等优先于别名**。`支援` 本身是正式词条，所以即使你在别名表里写了 `"支援": "支援机械"` 也不会生效。
- **别名优先于前缀**。`资深` 之所以解析成 `资深干员` 而不是报"歧义"（它同时是 `资深干员` 和 `高级资深干员` 的前缀），就是因为别名表里显式写了这一条。
- 想支持拼音之类的输入，直接加别名即可（例如 `"gjzz": "高级资深干员"`），匹配逻辑不用动。
- 前缀匹配是自动的：输入是某个正式词条的开头且只对得上一个词条时就会命中（`快速` → `快速复活`）。多个词条都能对上时会报错并列出候选，不会瞎猜。

## 输出

### 图片（默认）

暗色卡片流，每个词条组合一张卡片：

- 卡片左侧色条 = 该组合池子的**最低星级**颜色
- 右上角徽章 = 该组合的**星级区间**，如 `1★~5★`
- 卡片内是干员小块，按星级从高到低排列，颜色对应稀有度

版面尺寸在 Python 侧算好（卡片宽、每张卡片占几行、整图总宽总高），再用 `clip` 精确裁切，所以干员多图就大、干员少图就小。

`image_show_star` 打开后，干员名后面会跟上 `★5` 这样的星级标注。

### 纯文本

图片渲染不可用（`output_mode=text`、超过 `max_image_height`、或渲染服务报错）时自动降级为文本。每个组合一行标题，下面按星级分组列干员：

```
📋 公开招募 · 计算结果
输入：支援 输出 近战位 · 不限时长

1. 支援 + 输出 + 近战位
   ★5：诗怀雅
   ★4：杜宾
2. 支援 + 输出
   ★5：诗怀雅
   ★4：杜宾
```

结果太长时会按组合切分成多条消息，避免被平台截断。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `output_mode` | `image` | `image` 发图片（失败自动降级文本），`text` 只发文本 |
| `recruit_time` | `all` | `all` 展示所有时长下的可能结果；填具体时间（如 `9:00`）则只展示该时长能出的星级 |
| `image_show_star` | `false` | 图片中干员名后是否标 `★N` |
| `precise_image_size` | `true` | 用 `clip` 精确裁图。若你的文转图服务不支持 `clip` 导致图被裁坏，关掉改为整页截图 |
| `max_image_height` | `8000` | 图片超过这个高度就不画了，改发文本 |
| `text_chunk_limit` | `1200` | 文本单条长度上限，超出按组合切分成多条消息 |
| `auto_update` | `false` | 启动时检查上游干员数据并自动更新 |
| `update_interval_days` | `7` | 自动更新间隔 |

`output_mode` 填了不认识的值时会按 `text` 处理。

## 目录结构

```
main.py                    指令注册与流程编排
core/tags.py               词条归一化与别名表（改别名来这里）
core/data.py               干员数据加载 / 在线更新
core/calculator.py         子集枚举、时长星级区间、组合计算
core/text_view.py          文本输出（超长自动分条）
core/image_view.py         图片版面计算（卡片宽高、折行）
render/recruit/card.html   图片的 Jinja2 模板
data/recruit_operators.json 打包的干员数据集
tests/selftest.py          离线自测（不需要 AstrBot）
```

想调整配色、字号、间距，改 `render/recruit/card.html` 里的 CSS 即可；对应的尺寸常量在 `core/image_view.py` 顶部，两边必须同步改，否则 `clip` 裁切会对不上。
